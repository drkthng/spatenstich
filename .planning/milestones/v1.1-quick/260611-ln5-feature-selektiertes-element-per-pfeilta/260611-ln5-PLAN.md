<design_notes>
Diese Notizen fixieren die im Brief offen gelassenen Entscheidungen. Beim Implementieren befolgen.

## Geometrie-Konvention (aus bedLayout.ts + bestehendem Drag-Handler)
- `xM`/`yM` = Bbox-Center in Metern. Bildschirm-Y wächst nach unten.
- Richtungs-Mapping (deckt sich mit dem Maus-Drag-Handler, wo `dyM = (clientY - startY)/scale`):
  - ArrowLeft  → xM -= step
  - ArrowRight → xM += step
  - ArrowUp    → yM -= step
  - ArrowDown  → yM += step
- Clamping MUSS identisch zum bestehenden Drag-Move (WebPlanEditor.tsx `onMove`) sein:
  - `newXM = max(elWidth/2, min(dimensions.widthM - elWidth/2, candidateXM))`
  - `newYM = max(elHeight/2, min(dimensions.heightM - elHeight/2, candidateYM))`
  - elWidth/elHeight aus dem aktuellen Element lesen (`elements.find(e => e.id === selection)`).

## Schrittweiten — als benannte Konstanten (Brief-Constraint)
- `const ARROW_STEP_M = 0.1;`        // kleine Schrittweite (Pfeil ohne Modifier)
- `const ARROW_STEP_SHIFT_M = 0.5;`  // große Schrittweite (Shift+Pfeil)
- Hinweis: Es gibt KEIN Snap-to-Grid im Editor (Grid sind nur dekorative Meter-Linien, Drag ist freeform). Daher keine bestehende Grid-Schrittweite zum Wiederverwenden — die zwei Konstanten oben sind die Quelle der Wahrheit. Direkt unter `MOUSE_DRAG_THRESHOLD_PX` ablegen.

## Persistenz + zundo — gewählter Weg (Variante: Burst-Gesture-Wrapping)
Begründung: Ein nackter `updateElement` ohne gestureActive würde zwar via Autosave-Subscription persistieren, aber JEDEN Tastendruck als eigenen zundo-Snapshot ablegen (Key-Repeat flutet die 20er-History). Der frische l5y-Flush pausiert zundo bei gestureActive=true→false-Übergang und erzeugt genau EINEN Snapshot + persistiert über scheduleSaveElement. Genau das nutzen wir für einen Tasten-Burst.

Ablauf:
1. Erster Pfeil-Keydown im selektierten Zustand: falls noch nicht „im Move-Burst", `setGestureActive(true)` (snapshottet elements, pausiert zundo — siehe editorStore l5y-Subscription).
2. Jeder Pfeil-Keydown: `updateElement(selection, { xM, yM })` (läuft im pausierten Fenster → kein per-Tastendruck-Snapshot; Autosave bailt während gestureActive=true — Pitfall-5; korrekt, der Flush übernimmt).
3. Debounce-Timer (`ARROW_COMMIT_DEBOUNCE_MS = 400`) nach dem letzten Pfeil-Keydown: `setGestureActive(false)` → l5y-Subscription resumed zundo (1 Snapshot) UND flusht die geänderten Elemente über scheduleSaveElement → Outbox. Persistenz nachgewiesen.
4. Timer wird bei jedem weiteren Pfeil-Keydown zurückgesetzt (gleitendes Fenster → ein Burst = ein Snapshot).
- Den Debounce-Timer in einem `React.useRef<ReturnType<typeof setTimeout> | null>` halten und im useEffect-Cleanup clearen. Wenn beim Cleanup noch ein Burst offen ist (gestureActive war true), `setGestureActive(false)` aufrufen, damit kein hängendes gestureActive=true die spätere Autosave-Subscription blockiert.
- KEIN neuer Persistenz-Mechanismus: ausschließlich updateElement + setGestureActive verwenden (gleicher Pfad wie Maus-Drag-Release).

## Fokus- + Plattform-Guard
- Web-only: Listener lebt bereits in WebPlanEditor.tsx (nur Web gerendert). Kein zusätzlicher `Platform.OS`-Guard nötig — die Komponente ist Web-only. Trotzdem `typeof window !== 'undefined'`-Sicherheit ist durch den bestehenden `window.addEventListener`-useEffect schon gegeben.
- Eingabefeld-Guard (bestehendes Muster im Delete/Escape-useEffect erweitern bzw. spiegeln):
  - `const tag = (e.target as HTMLElement)?.tagName;` → INPUT/TEXTAREA aussparen.
  - Zusätzlich contenteditable prüfen: `const active = document.activeElement as HTMLElement | null;` → wenn `active?.isContentEditable` oder dessen tagName INPUT/TEXTAREA, NICHT behandeln.
- Selektions-Guard: nur behandeln, wenn `selection` gesetzt UND ein nicht-gelöschtes Element dazu existiert.
- `e.preventDefault()` NUR aufrufen, wenn tatsächlich verschoben wird (Selektion + Pfeiltaste + nicht in Eingabefeld). Andernfalls return ohne preventDefault → Seiten-Scroll bleibt erlaubt.

## Listener-Verortung
- Bevorzugt: den bestehenden Delete/Escape-`keydown`-useEffect (WebPlanEditor.tsx Zeilen ~118-133) um die Arrow-Behandlung erweitern, ODER einen zweiten, eigenständigen `keydown`-useEffect anlegen. Eigener useEffect ist sauberer (Burst-Timer-Ref + Cleanup gekapselt) — empfohlen. Der Delete/Escape-Effekt bleibt unverändert (keine Regression).
- Dependency-Array des Arrow-useEffect: `[selection, scale, dimensions.widthM, dimensions.heightM, elements]` (analog zum Drag-Effekt; elements für aktuelle Bbox/Position).
</design_notes>

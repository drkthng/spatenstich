## Decisions Made

- **Detection-first idempotency only on promoteBedDraft**: matches RESEARCH §Open Question 4 resolution. promotePlantDraft and promoteObservationDraft do not run an idempotency check on themselves — the caller (Plan 04 review screen) refreshes the pending-drafts list after each promote, so a draft whose status flipped to 'promoted' will not re-appear. Adding parallel checks to all three would require threading `existingElements` through the plant and observation signatures and was rejected as scope creep.
- **dismissDraft is generic over draft entities**: a single function with `entity: 'bed_drafts' | 'plant_drafts' | 'observation_drafts'` parameter and a row-union argument. The runtime cast to `EntityName` + `AnyRow` is safe because the caller controls both. Alternative (per-entity dismiss functions) was rejected as boilerplate.
- **nextFreeBedSlot exported**: the plan's `<acceptance_criteria>` required `export function nextFreeBedSlot`. Beyond that hard requirement, exporting makes the layout testable as a pure function (5 tests run without storage mocks) and lets Plan 04 preview placement before committing.
- **promoteObservationDraft's `_importItemId` parameter intentionally unused**: keeps the function signature symmetric with the other two promoters for caller convenience, and reserves the parameter for a future use (e.g. linking observation status back to import_items). Today it is purely a placeholder.
- **Confidence-band helper extracted as confidenceToBand()**: maps 0..1 number to 'high' / 'medium' / 'low' / null. Same thresholds as the existing TrafficLightBadge component (0.8 → high, 0.6 → medium, < 0.6 → low). Tested explicitly across all three branches in draftPromotionRepo.test.ts.
- **Added one extra test in idempotency suite + one in layout suite** beyond the Wave-0 shells: idempotency gained a soft-delete edge case (a former dup that has been soft-deleted must NOT block a fresh promote — exercises the negative branch); layout gained a soft-deleted-beds-ignored test. Both extras directly cover the `deletedAt === null` filter in the production code and strengthen the verification gate. Not a deviation — additive within the plan's "all formerly-it.todo tests now have real assertions" rule.

### Plan-spec adjustments (no semantic deviation)

- **GardenDimensionsRow.shape value**: plan example used `shape: 'rect'` in test fixtures, but the type union is `'rectangle' | 'l_shape' | 'trapezoid' | 'freehand'`. Used `'rectangle'` in fixtures. No production-code impact.
- **GardenDimensionsRow.extraDims field**: required by the type but missing from the plan's fixture examples. Added `extraDims: null` to all test fixtures. No production-code impact.
- **PlantDraftRow.stageEstimate value**: plan example used `'Jungpflanze'` (German free text) but the type is `string | null` with the import payload using English-stage enums (`'seedling' | 'vegetative' | 'flowering' | 'fruiting' | 'senescent'`). Used `'vegetative'` in the fixture for type-correctness; behavior is identical (the test only asserts elementType + provenance.parentBedId, never the stage).

The implementation uses `as unknown as AnyRow` with an explicit generic `<AnyRow>` — semantically equivalent, lints cleaner. Both cast styles are present in the codebase (gardenPlanRepo.ts vs. importRepo.ts).

## Trigger-Geste (wie öffnet sich der Editor)

| Option | Description | Selected |
|--------|-------------|----------|
| Doppelklick (Web) + Long-Press (Mobile) | Native Gesten je Plattform. Im Web Doppelklick wie gewohnt, auf iPhone ~500ms gedrückt halten. Kein zusätzlicher Button im Toolbar nötig. | ✓ |
| Single-Tap → 'Bearbeiten'-Button im Toolbar | Element selektieren, dann Button drücken. Konsistent zwischen Plattformen, sichtbarer Affordance. Mehr Klicks für jede Änderung. | |
| Beides parallel anbieten | Doppelklick/Long-Press UND Button — Power-User und Entdecker happy. Etwas mehr Code, aber kein Konflikt. | |

**User's choice:** Doppelklick (Web) + Long-Press (Mobile)
**Notes:** Native Gesten bevorzugt — kein zusätzlicher Toolbar-Button.

---

## Resize + Rotate Interaktion

| Option | Description | Selected |
|--------|-------------|----------|
| Nur Modal mit Zahlen-Inputs (cm + Grad) | Präzise, cross-platform identisch, einfach zu bauen. Skia 2-Finger-Rotation bleibt zusätzlich aktiv. Weniger "direkt" aber klar. | |
| Modal + Drag-Handles auf Canvas | Modal für Präzision (Zahlen eingeben), Eck-Handles zum Resize per Maus/Touch, separater Rotations-Handle. Beste UX, deutlich mehr Code. | ✓ |
| Nur Drag-Handles, keine Zahlen | Direktmanipulation überall, kein Modal-Wechsel. Schwer präzise (z.B. exakt 90° oder genau 60cm) ohne Snap-Punkte. | |

**User's choice:** Modal + Drag-Handles auf Canvas
**Notes:** Hybrid-Ansatz: Modal für Präzision, Handles für direkte Manipulation.

## Eigenschaften-Umfang (optionale Felder über Name/Größe/Rotation hinaus)

| Option | Description | Selected |
|--------|-------------|----------|
| Notiz / Bemerkung (Freitext) | Z.B. "gepflanzt 2026-05-20, Vorkultur Fensterbank". Persistiert in provenance.note. | ✓ |
| Pflanzdatum (Date-Picker) | Wann hast du es gesetzt? Wertvoll für Aussaatkalender-Abgleich (Phase 10). DatePicker nötig. | ✓ |
| Farbe (Custom-Akzentfarbe) | User wählt Akzentfarbe — z.B. um eigene Sorten visuell zu gruppieren. Color-Picker nötig, nice-to-have. | ✓ |
| Keine, nur Name/Größe/Rotation/Z-Order | Minimaler Scope. Notiz/Datum/Farbe später in eigener Phase. | |

**User's choice:** Alle drei optionalen Felder (Notiz, Pflanzdatum, Farbe)
**Notes:** Vollständig ausgebaut. Erweiterte Felder werden default-collapsed angezeigt um Modal nicht zu überladen.

## Z-Order Steuerung (bei Überlappung)

| Option | Description | Selected |
|--------|-------------|----------|
| Photoshop-Style Buttons im Modal | Vier Buttons: "Ganz nach vorne", "Eine Ebene vor", "Eine Ebene zurück", "Ganz nach hinten". Vertraut, ein Klick. | ✓ |
| Numerisches Feld (z.B. 0–99) | Direkter Wert eingeben. Maximale Kontrolle, aber unintuitiv ("warum ist 5 vor 3?"). | |
| Drag-Drop-Liste aller überlappenden Elemente | Modal zeigt Liste der überlappenden Items, drag zum Sortieren. Sehr explizit, mehr UI-Code, ungewohnt auf Mobile. | |

**User's choice:** Photoshop-Style Buttons im Modal
**Notes:** Vertrautes Pattern; speichert provenance.zOrder als Integer.

---

## Rotation Snap-Winkel (beim Drag-Handle)

| Option | Description | Selected |
|--------|-------------|----------|
| Snap bei 15°-Schritten | Beim Drag rastet die Rotation bei 0/15/30/45/60° etc. ein. Shift-Taste deaktiviert Snap. Standard in CAD/Design-Tools. | ✓ |
| Snap nur bei 45°-Schritten | Gröber, aber genügt für Beet-Ausrichtung. Weniger "wackelig". | |
| Freie Rotation, kein Snap | Pixel-Genau überall. Im Modal kann der User exakte Grad-Werte eintippen wenn nötig. | |

**User's choice:** Snap bei 15°-Schritten (Shift deaktiviert)
**Notes:** Standard-Verhalten aus Figma/CAD-Tools.

---

## Long-Press Verhalten auf Skia (Disambiguierung)

| Option | Description | Selected |
|--------|-------------|----------|
| Long-Press öffnet Editor; Tap selektiert; Drag verschiebt | Drei klar getrennte Gesten. ~500ms ohne Bewegung triggert Editor-Modal. | ✓ |
| Long-Press nur auf bereits selektiertem Element | Erst tippen zum Selektieren, dann halten für Editor. 2-Schritt-Workflow. | |
| Kein Long-Press auf Mobile — nur Edit-Button im Toolbar | Trigger-Geste platform-spezifisch: Web=Doppelklick, Mobile=Toolbar-Button. | |

**User's choice:** Long-Press öffnet Editor (direkt, ohne vorherige Selektion)
**Notes:** Drei Gesten parallel: tap=select, drag=move, long-press=edit. Disambiguierung via `gesture-handler` `LongPress.minDuration(500) + maxDistance < 10px`.

## Claude's Discretion

- **Drag-Handle Visualisierung**: Größe/Farbe/Schatten der Eck-Handles und des Rotations-Handles — Default-Style passend zum existierenden cyan-dashed Selection-Outline.
- **Modal-Größe und -Position**: Bottom-Sheet auf Mobile (wenn passend), centered auf Web.
- **Validierungs-Regeln**: Sinnvolle Min/Max für widthM, heightM (z.B. 5–500cm).
- **Cross-Platform Date- und Color-Picker**: Bevorzugt aus react-native-reusables; Fallback auf etablierte RN-Libs mit Web-Support.
- **Element-Form-Anpassung**: Wie genau Eck-Handles auf Kreisen (Pflanzen) vs. Rechtecken (Beete) aussehen — Claude entscheidet sinnvoll.

### Test 1: Skia Long-Press öffnet Modal

**Plattform:** iOS-Simulator (oder physisches iPhone)
**Requirement:** D-01, D-02
**Voraussetzung:** App läuft im Expo Go oder Development Build auf iOS. Gartenplan mit mindestens einem Element geöffnet.

**Schritte:**
1. Starte `expo start` und öffne die App auf dem iOS-Simulator.
2. Navigiere zum Plan-Editor (Tab "Plan").
3. Tippe kurz auf ein vorhandenes Element — es sollte sich selektieren (kein Modal).
4. Drücke dasselbe Element mindestens 500 ms lang ohne dabei die Position zu verändern.
5. Beobachte ob das ElementEditorModal erscheint.

**Erwartung:** Nach ca. 500 ms Long-Press öffnet sich das ElementEditorModal mit dem Titel "Element bearbeiten". Das Element bleibt selektiert. Kurzes Antippen öffnet KEIN Modal (D-02 Disambiguation).

**Bei Fehlschlag:** Plan 09.1-02 (EditorCanvas LongPress-Trigger, `useEditorLongPress`-Hook) erneut prüfen. Threat: T-09.1-MODAL-ESC.

### Test 5: 15°-Snap UX-Feel beim Drehen

**Plattform:** Desktop-Browser (oder iOS-Simulator)
**Requirement:** D-07
**Voraussetzung:** App geöffnet, Element selektiert, Rotations-Handle sichtbar (kleiner Kreis oberhalb des Elements).

**Schritte:**
1. Selektiere ein Element im Plan-Editor (einmal klicken/tippen).
2. Ziehe den Rotations-Handle (oben mittig am Element) langsam in einem Kreis.
3. Beobachte ob die Rotation in 15°-Schritten einrastet (Snap-Verhalten, z.B. 0°, 15°, 30°, 45° ...).
4. Auf Web: Halte zusätzlich die Shift-Taste gedrückt und ziehe erneut — Snap muss deaktiviert sein (freies Drehen).
5. Öffne das Modal via Doppelklick und gib einen exakten Wert ins Rotations-Feld ein (z.B. "37°") — dieser Wert wird ohne Snap gespeichert.

**Erwartung:** Ohne Shift rastet die Rotation in 15°-Schritten ein. Mit Shift (Web) ist freies Drehen möglich. Im Modal kann eine beliebige Gradzahl ohne Snap eingegeben werden.

**Hinweis:** Shift-Halten auf Web deaktiviert den Snap (D-07 Shift-Bypass). Mobile hat keinen Shift-Key — dort ist der Snap immer aktiv beim Drag, aber die exakte Grad-Eingabe im Modal umgeht den Snap.

**Bei Fehlschlag:** Plan 09.1-01 (`snapToAngle`-Algorithmus in editorStore) oder Plan 09.1-03 (RotationHandle Gesture-Handler) erneut prüfen. Threat: T-09.1-HANDLE-DRIFT.

### Test 6: Drag-Latency < 16ms (Resize-Handle auf iOS-Simulator)

**Plattform:** iOS-Simulator (Skia-Renderer)
**Requirement:** D-22 (gestureActive zundo pause/resume, 60fps)
**Voraussetzung:** iOS-Simulator mit Development Build (Hermes + Skia aktiv).

**Schritte:**
1. Selektiere ein Element im Plan-Editor auf dem iOS-Simulator.
2. Greife einen der 4 Eck-Handles (Resize-Handles an den Ecken des Elements).
3. Ziehe den Handle langsam und schnell — das Element soll in Echtzeit folgen.
4. Optional: Aktiviere das Skia FPS-Overlay (`Skia.SkiaDomView.debugFlags` oder React Native Dev Menu → "Show Perf Monitor") um den Frame-Counter zu beobachten.
5. Beobachte ob Frames unter 60fps fallen (Frame-Drop sichtbar als Ruckeln).

**Erwartung:** Das Element folgt dem Handle ohne wahrnehmbare Verzögerung (< 16ms = 60fps). Kein Ruckeln beim schnellen Ziehen. Skia Worklet-Animationen (Reanimated) halten die Latenz im GPU-Thread.

**Hinweis:** Bei Ruckeln ist oft der JS-Thread blockiert oder zundo-Undo-Stacks werden während des Drags geschrieben (D-22 Mitigation: gestureActive pausiert zundo).

**Bei Fehlschlag:** Plan 09.1-01 (`gestureActive`-Flag + zundo `pause`/`resume`) oder Plan 09.1-03 (Resize-Handle worklet-Implementierung) erneut prüfen. Threat: T-09.1-HANDLE-DRIFT.

### Test 7: Color-Picker Cross-Platform (iOS + Android + Web)

**Plattform:** iOS, Android UND Web (alle drei separat)
**Requirement:** D-10
**Voraussetzung:** App auf allen drei Plattformen startbereit. Element vorhanden.

**Schritte:**
1. Öffne das ElementEditorModal via Long-Press (iOS/Android) oder Doppelklick (Web).
2. Scrolle zur Sektion "Akzentfarbe" (evtl. unter "Erweitert" verborgen — Tap/Klick auf "Erweitert" öffnet die Sektion).
3. Öffne den Color-Picker (Tap auf die Farbvorschau oder "Akzentfarbe"-Feld).
4. Gib einen konkreten Hex-Wert ein, z.B. `#e83c3c` (Rot).
5. Bestätige die Auswahl und speichere das Modal ("Speichern").
6. Öffne das Modal erneut — der Hex-Wert muss unverändert `#e83c3c` sein (Persistenz via `provenance.accentColor`).

**Erwartung iOS/Android:** `reanimated-color-picker@3.0.6` öffnet sich als nativer Picker. Hex-Eingabe funktioniert. Wert wird in `provenance.accentColor` gespeichert und nach Modal-Neuöffnung korrekt angezeigt.

**Erwartung Web:** Web-Fallback (`<input type="color">` oder Library-Web-Build) öffnet Browser-nativen Color-Picker. Hex-Wert wird korrekt übernommen und persistiert.

**Hinweis:** Falls iOS und Android-Native sowie Web abweichendes Verhalten zeigen (z.B. Web-Picker akzeptiert kein manuelles Hex-Eingabe), bitte beide separat ankreuzen.

**Bei Fehlschlag:** Plan 09.1-02 (ElementEditorMoreFields, `reanimated-color-picker`-Integration) oder Plan 09.1-00 (Library-Install, `@react-native-community/datetimepicker`) erneut prüfen. Threat: T-09.1-I18N.

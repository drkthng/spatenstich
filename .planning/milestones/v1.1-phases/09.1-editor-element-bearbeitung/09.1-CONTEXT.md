# Phase 09.1: Editor-Element-Bearbeitung - Context

**Gathered:** 2026-05-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Erweitert den existierenden Plan-Editor (Web SVG + iPhone Skia) um vollständige
Element-Bearbeitung nach dem ersten Platzieren: Größe, Rotation, Eigenschaften,
Z-Order. Heute kann der User nur platzieren und verschieben — danach ist das
Element "festgenagelt". Diese Phase löst das.

**In-Scope:**
- Trigger-Geste zum Öffnen eines Element-Editors (Doppelklick/Long-Press)
- Modal mit allen editierbaren Eigenschaften
- Drag-Handles auf Canvas für direkte Resize/Rotation
- Z-Order-Steuerung für überlappende Elemente
- Persistenz aller neuen Eigenschaften (über existierendes `provenance`-Feld)

**Out-of-Scope (eigene Phasen):**
- Multi-Select / Gruppen-Bearbeitung
- Copy/Paste von Elementen
- Element-Bibliothek mit Templates
- Vereinsregeln-Validierung beim Resize (Phase 16)
- Aussaatkalender-Verknüpfung beim Pflanzdatum (Phase 10 nutzt das Feld)

</domain>

<decisions>
## Implementation Decisions

### Trigger-Geste (wie öffnet sich der Editor)
- **D-01:** Plattform-spezifische native Gesten:
  - **Web (SVG):** Doppelklick auf Element öffnet Modal
  - **Mobile (Skia):** Long-Press ~500ms ohne Bewegung öffnet Modal
- **D-02:** Drei klar getrennte Gesten auf Skia: `tap` = selektieren, `drag` =
  verschieben, `long-press` = Editor öffnen. Long-Press muss explizit von
  Pan-Gesture disambiguiert werden (gesture-handler `LongPress.minDuration(500)`
  + `maxDistance < 10px`).
- **D-03:** Kein zusätzlicher "Bearbeiten"-Button im Toolbar (Trigger reicht).

### Resize + Rotation Interaktion
- **D-04:** Hybrid-Ansatz: **Modal mit Zahlen-Inputs + Drag-Handles auf Canvas**
  - Modal: präzise Werte eintippen (cm, Grad)
  - Drag-Handles: direkte Manipulation für schnelle Anpassung
- **D-05:** **Eck-Handles** (4 Punkte) für Resize. Kein separates Width/Height
  am Edge-Mid — Eck reicht für MVP. Drag-zum-Verkleinern/Vergrößern, proportional
  mit Shift gehalten (Web), Maintain-Ratio per Modal-Checkbox (Mobile).
- **D-06:** **Separater Rotations-Handle**: kleiner runder Punkt mittig über
  dem Element (16–24px Offset). Klassisches Pattern (Figma/Skia).
- **D-07:** **Rotation Snap bei 15°-Schritten** beim Drag. Shift-Taste (Web)
  deaktiviert Snap für freie Rotation. Im Modal: exakte Grad-Eingabe ohne Snap.
- **D-08:** Skia-Editor: existierende 2-Finger-Rotations-Geste bleibt aktiv;
  Drag-Handle ist additiv für 1-Finger-Bedienung.

### Eigenschaften im Modal
- **D-09:** **Kern-Felder** (immer sichtbar):
  - Name / Label (TextInput)
  - Breite × Höhe in cm (zwei NumericInputs)
  - Rotation in Grad (NumericInput 0–359)
  - Z-Order (4 Buttons, siehe D-12)
- **D-10:** **Erweiterte Felder** (collapsible "Mehr"-Section, optional):
  - Notiz / Bemerkung (multi-line Freitext) — `provenance.note`
  - Pflanzdatum (Date-Picker) — `provenance.plantedAt` (ISO-Date)
  - Custom-Akzentfarbe (Color-Picker) — `provenance.accentColor` (hex)
- **D-11:** Erweiterte Felder default-collapsed um Modal nicht zu überladen.
  Counter "(3)" am Toggle wenn Werte gesetzt sind.

### Z-Order Steuerung
- **D-12:** **Photoshop-Style Buttons** im Modal:
  - "⤒ Ganz nach vorne" / "↑ Eine Ebene vor" / "↓ Eine Ebene zurück" / "⤓ Ganz nach hinten"
- **D-13:** **Speicherung:** `provenance.zOrder: number` (Integer, default 0).
  Render-Sortierung: ascending; höhere Z-Order = oben.
- **D-14:** **Conflict-Resolution:** Bei "Eine Ebene vor" alle anderen Elemente
  im selben Beet mit ≥ aktueller zOrder analysieren → nächst-höhere Z finden +1
  setzen. Keine globale Renumbering-Logik (lazy).
- **D-15:** Z-Order ist **plan-weit** (nicht beet-lokal). Einfacher und mit
  bestehender flacher `plan_elements`-Struktur konsistent.

### Modal-Pattern
- **D-16:** Follow `BedPickerModal.tsx` pattern: React Native `<Modal>` +
  NativeWind + `<Card>` aus `components/ui/card`. Buttons via `<Button variant>`.
- **D-17:** Modal-Footer: "Abbrechen" (links, ghost) + "Speichern" (rechts,
  primary). "Löschen"-Button als destructive variant zusätzlich verfügbar
  (statt umweg über Selektion + Del-Key).
- **D-18:** ESC schließt Modal (Web); Hardware-Back schließt (Android).
  Pending changes verwerfen oder bestätigen? → **immer verwerfen ohne
  Confirm**, da Undo (Ctrl+Z) das auffängt.

### Datenmodell
- **D-19:** **Keine neue DB-Migration nötig.** Alle neuen Felder leben in
  `plan_elements.provenance: jsonb`:
  - `provenance.rotateDeg` (existiert bereits aus Phase 7)
  - `provenance.zOrder: number`
  - `provenance.note: string`
  - `provenance.plantedAt: string` (ISO-Date)
  - `provenance.accentColor: string` (hex)
- **D-20:** **`widthM` und `heightM`** sind bereits dedizierte Spalten — Resize
  nutzt direkten Patch via `updateElement(id, { widthM, heightM })`.
- **D-21:** **`label`** ebenfalls bereits dedizierte Spalte (siehe entities.ts).

### Undo/Redo
- **D-22:** Jede Bearbeitung muss `updateElement()` aufrufen — zundo captured
  automatisch in 20-Step-History. **Eine Modal-Speicherung = ein Undo-Snapshot**.
  Drag-Handle-Bewegungen: Live-Preview während Drag, ein Snapshot bei `onEnd`
  (Pattern: `setGestureActive(true)` während Drag, `updateElement()` final am Ende).

### i18n (Deutsch zuerst)
- **D-23:** Neue i18n-Keys unter `editor.elementEditor.*`:
  - `title`, `name`, `width`, `height`, `rotation`, `zOrder`, `note`, `plantedAt`,
    `accentColor`, `bringToFront`, `bringForward`, `sendBackward`, `sendToBack`,
    `cancel`, `save`, `delete`, `moreFields`, `lessFields`
- **D-24:** UTF-8 Umlaute strikt (siehe Memory `feedback_german_umlauts.md`).

### Claude's Discretion
- Drag-Handle Visualisierung (Größe, Farbe, Schatten) — Default-Style passend
  zu existierendem cyan-dashed Selection-Outline.
- Modal-Größe und -Position (centered vs bottom-sheet auf Mobile) — Bottom-Sheet
  auf Mobile wenn passend, centered auf Web.
- Validierungs-Regeln (min/max für widthM, heightM, rotation) — Sinnvolle
  Defaults wählen (z.B. width 5–500cm).
- Cross-Platform Date-Picker und Color-Picker Auswahl — bevorzugt aus
  react-native-reusables falls vorhanden, sonst etablierte RN-Libs mit
  Web-Support.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **`updateElement(id, patch)` in editorStore**: Naturally hits zundo undo-history
  + autosave. Alle neuen Bearbeitungen rufen diese Action auf.
- **`BedPickerModal.tsx`**: Vorbild für ElementEditor-Modal — React Native Modal +
  NativeWind + Card-Komponente.
- **`provenance: jsonb`** auf `plan_elements`: Free-form Metadata-Feld, in Phase 7
  bereits etabliert (`rotateDeg`). Erweiterbar ohne Migration.
- **2-Finger-Rotations-Geste auf Skia**: Bleibt aktiv, neuer Drag-Handle ist
  additiv für 1-Finger / Maus-Nutzer.
- **`setGestureActive(bool)`-Flag**: Pattern für Live-Drag ohne Autosave-Spam.
  Resize/Rotate-Handles müssen das nutzen.

### Established Patterns
- **NativeWind-Forms**: `<Card><CardHeader><CardContent>` + `<Button variant>`
  aus `components/ui/*`.
- **i18n via `t(key)` utility**: Nested-Path-Lookup auf de.json. Neue Keys unter
  `editor.elementEditor.*` einsortieren.
- **Soft-Delete via `deletedAt`**: Falls "Löschen" im Modal — verwendet
  existierendes Pattern.
- **Selection-Stroke (cyan dashed)**: Visuell konsistent mit neuem Handle-Style.

### Integration Points
- **Web Doppelklick**: Neuer `onDoubleClick`-Handler auf SVG-Element. Heute nur
  `onMouseDown` + `onClick` vorhanden.
- **Skia Long-Press**: `Gesture.LongPress().minDuration(500).maxDistance(10)`
  → triggert `openElementEditor(id)` action.
- **Render-Sortierung**: Aktuelle Editoren rendern Elements in DB-Reihenfolge
  (vermutlich `created_at`). Beide Renderer müssen auf
  `sortByZOrder(elements)` umgestellt werden.
- **Rotation-Rendering**: SVG noch nicht `<g transform="rotate(...)">` —
  hinzufügen. Skia: Path-Rotation rendern (heute nur stored, nicht visualisiert).

</code_context>

<specifics>
## Specific Ideas

- **Photoshop-Style Z-Order Buttons** sind das vertraute Pattern, das der User
  explizit gewählt hat — kein Skia-Eigenbau, sondern bekannte Reihenfolge:
  `Ganz nach vorne / Eine vor / Eine zurück / Ganz nach hinten`.
- **15°-Snap** ist Standard in CAD/Design-Tools — User-Erwartung erfüllt.
- **Hybrid Modal + Handles**: User will sowohl präzise (Modal) als auch direkt
  (Handles) — beides erst zusammen ist "schick".

</specifics>

<deferred>
## Deferred Ideas

- **Multi-Select + Gruppen-Resize/Rotate**: Eigene zukünftige Phase. Würde
  Selection-Modell erweitern (single → array).
- **Copy/Paste, Duplicate**: Eigene Phase.
- **Element-Templates / Bibliothek** ("favorisierte Beet-Maße"): Phase 11+
  (Garten-Journal) als Beobachtungs-Feld evtl. relevant.
- **Snap-to-Grid für Resize**: Sinnvoll, aber separate Entscheidung (Polygon-Snap
  in Phase 7.5b angedeutet). Hier nicht implementieren.
- **Constraint-Validierung beim Resize** (Mindestabstand zu Nachbar-Pflanze, etc.):
  Phase 9 hat Companion-Hinweis ähnlich — analoges Pattern könnte hier auf
  Beet-Grenzen angewandt werden. Hier nur weiches Clamp an Garten-Bounds.
- **Animations / Transitions beim Modal-Open**: Phase 14 (Modernes Design).

</deferred>

## Component Inventory

### 1. CompanionToast (new component)

**File:** `app/src/components/editor/CompanionToast.tsx`

**Purpose:** Floating toast banner positioned above the editor toolbar. Distinct from `InlineBanner` (which lives in the layout flow). CompanionToast is absolutely positioned, non-blocking, auto-dismisses.

**Layout:**
```
[position: absolute, bottom: toolbar_height + 16px, left: 16px, right: 16px]
┌─────────────────────────────────────────────────────────────────┐
│ ▏ [Icon 16px]  [message text 14px]              [X 44×44px]    │
│ ▏  border-l-4                                                   │
└─────────────────────────────────────────────────────────────────┘
```

**Variants:**
- `variant: 'error'` — `border-l-4 border-red-600 bg-red-50 dark:bg-red-950` + `AlertTriangle` icon at `#DC2626`
- `variant: 'success'` — `border-l-4 border-green-600 bg-green-100 dark:bg-green-950` + `CheckCircle` icon at `#16A34A`

**Props:**
```typescript
interface CompanionToastProps {
  variant: 'error' | 'success';
  message: string;          // pre-interpolated i18n string
  autoDismissMs?: number;   // default: 4000
  onDismiss?: () => void;
  testID?: string;
}
```

**Behaviour:**
- Auto-dismiss after `autoDismissMs` (default 4000ms) via `setTimeout` — cleared on manual dismiss or unmount.
- Dismiss X button: `min-h-[44px] min-w-[44px]`, `accessibilityRole="button"`, `accessibilityLabel="Hinweis schließen"`.
- When both error and success banners are triggered simultaneously: render only the `'error'` variant (D-08: conflict has priority). Multiple conflict plant names are joined in a single message.
- `animated` entrance: slide-up from bottom via `react-native-reanimated` `withTiming` (200ms, easing `Easing.out(Easing.quad)`). Exit: fade-out 150ms before removal.
- **Does not block canvas interaction.** `pointerEvents="box-none"` on the container.

### 2. InlineBanner variant extension (existing component modified)

**File:** `app/src/components/InlineBanner.tsx`

**Change:** Add `'error'` and `'success'` to the `variant` prop union. Apply same colour logic as CompanionToast when these variants are active.

| Variant | Border | Background | Icon | Icon color |
|---------|--------|------------|------|------------|
| `'warning'` (existing) | `border-amber-500` | `bg-amber-50 dark:bg-amber-950` | `AlertCircle` | `#D97706` |
| `'error'` (new) | `border-red-600` | `bg-red-50 dark:bg-red-950` | `AlertTriangle` | `#DC2626` |
| `'success'` (new) | `border-green-600` | `bg-green-100 dark:bg-green-950` | `CheckCircle` | `#16A34A` |

Note: Phase 9 uses `CompanionToast` (floating) — not `InlineBanner` — for companion hints. The InlineBanner variant extension is a preparatory refactor so future phases can use `error`/`success` inline.

### 3. Skia conflict triangle overlay (canvas)

**Rendered inside:** `EditorCanvas.tsx` (or a dedicated `ConflictOverlay` sub-component within the Skia `<Canvas>`)

**Shape:** Right-pointing equilateral triangle, 14×14 canvas-pixel bounding box.
**Position:** Top-right corner of the plant element's bounding rectangle, offset `(+2px, −2px)` outward (so it sits outside the element boundary, not over the label).
**Paint:**
- Fill: `#DC2626` at 90% opacity (`Alpha: 230`)
- No stroke
**Skia API:** `<Path>` primitive with computed triangle path. Do not use `<Polygon>` (not exported in Skia v1). Path string: `M 0 0 L 14 7 L 0 14 Z` (pointing right), translated to element's top-right corner.

**Visibility rules:**
- Shown: plant element has `incompatible` companion relationship with at least one other plant in the same bed.
- Hidden: no `incompatible` relationship, or plant has no `plantSlug` in provenance (D-14), or plant is outside all beds (D-04).
- Updated: recomputed via `useMemo` on every `elements` change (D-11).

**Accessibility:** The canvas is not accessible to screen readers by default (Skia limitation). No additional a11y markup required for the triangle overlay — the CompanionToast banner is the accessible equivalent.

## Copywriting Contract

All strings live in `packages/shared/src/i18n/de.json` under the `companion` namespace (new key block).

### New i18n keys to add: `de.companion`

```json
{
  "companion": {
    "conflict_single": "⚠ Konflikt: {{plantA}} verträgt sich nicht mit {{plantB}}",
    "conflict_multi": "⚠ Konflikt: {{plantA}} verträgt sich nicht mit {{others}}",
    "good_single": "✓ Gute Nachbarschaft: {{plantA}} + {{plantB}}",
    "good_multi": "✓ Gute Nachbarschaft: {{plantA}} + {{others}}",
    "dismiss": "Hinweis schließen"
  }
}
```

**Interpolation rules:**
- `{{plantA}}` = the label of the plant just placed (from `element.label`).
- `{{plantB}}` = the label of the single conflicting/companion neighbour.
- `{{others}}` = comma-joined list of neighbour labels when >1 (e.g. `"Fenchel, Erbse"`).
- Use `element.label` for display (not `plantSlug`). If plant DB has `iconEmoji`, prepend it: `"🍅 Tomate"` (D-07 / specifics section).

**Plant name formatting rule:** If `plant.iconEmoji` is available from the Plant-DB lookup, display name = `"${iconEmoji} ${nameDe}"`. Otherwise display name = `element.label` alone. This applies in both `{{plantA}}` and all `{{others}}` positions.

## Interaction Contract

### Trigger → Detection → Display sequence

1. **Placement / Move** (`addElement` or `updateElement` fired in `editorStore`):
   - Hook intercepts action via Zustand `subscribe`.
   - Computes affected plant's bed membership (provenance.parentBedId first, PiP fallback — D-03).
   - Runs `loadCompanionsFor(plantId)` against local cache (synchronous — D-02).
   - Filters neighbours in same bed by `plantSlug`.
   - Result: `{ conflicts: PlantRow[], companions: PlantRow[] }`.
   - If `conflicts.length > 0`: show `'error'` CompanionToast (suppress any pending `'success'` toast — D-08).
   - Else if `companions.length > 0`: show `'success'` CompanionToast.
   - Else: no toast.

2. **Plan load** (retroactive check — D-01b):
   - Run detection for all plant elements after elements are loaded into `editorStore`.
   - Populate `conflictElementIds: Set<string>` in derived state / local hook state.
   - Do NOT show toasts for plan-load conflicts (too noisy). Only update the triangle overlay set.
   - Summary notification for plan-load conflicts is deferred to v2 (DEFERRED).

3. **Auto-dismiss**: 4000ms after last show. Timer resets if a new toast fires before dismiss.

4. **Manual dismiss**: X button in CompanionToast. Removes toast immediately. Does NOT remove the triangle overlay (overlay persists until conflict is resolved).

5. **Conflict resolved** (conflicting plant deleted or moved out of bed):
   - `updateElement` / `deleteElement` triggers re-detection for all plants in the affected bed.
   - Triangle overlay removed from previously-conflicting plant(s) if no remaining conflicts.
   - No "conflict resolved" toast shown.

### Non-blocking guarantee

No confirmation dialog. No "Trotzdem platzieren?" button. No placement gate. The plant is placed regardless. The toast is informational only (D-06, Specifics).

### Position

CompanionToast is absolutely positioned above the toolbar. Toolbar height is obtained from the editor layout (existing pattern). Bottom offset: `toolbar_height + md (16px)`. Left/right margin: `md (16px)`.

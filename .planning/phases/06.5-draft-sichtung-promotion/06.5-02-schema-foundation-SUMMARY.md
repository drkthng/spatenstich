## Decisions Made

- **Test file location:** Existing `rowMappers.test.ts` lives at `app/src/lib/__tests__/rowMappers.test.ts` (not the `mappers/__tests__/` path written in the plan's `files_modified` list — that directory doesn't exist in the codebase). Used the existing location to keep a single test entry point. The plan's intent was satisfied: 3 new tests covering DB-emit, local-default-null, and full-round-trip.
- **Non-optional nullable shape:** `importedFrom: string | null` (not `importedFrom?: string`). Matches existing `confidence: 'high' | 'medium' | 'low' | null` style. Constructors are forced to populate — no silent partial-update bugs when copying with `{ ...existing, ...patch }`.
- **DbPlanElementRowLoose stays loose:** New DB fields added as `imported_from?: string | null` (still optional on the DB side). This is deliberate: rows that exist before Migration 017 push will have these columns missing, and the mapper's `?? null` default handles that gracefully without a backfill.
- **importEntityToDb gains a symmetry entry:** `importedFrom: 'imported_from'` added to camelToSnakeMap even though no draft type currently has this field. This is defensive — if Plan 03/04 ever wants to push a draft with an importedFrom field, the generic mapper handles it automatically.
- **gardenPlanRepo.test.ts fixture fix is in-scope:** TS surfaced 3 missing fields when PlanElementRow was extended. This is a direct, mechanical consequence of Task 2. Adding `importedFrom: null, provenance: null` to the 3 affected fixtures keeps the same in-commit (Rule 1 auto-fix). Not a deviation — same task.

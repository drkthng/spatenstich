### Gaps Summary

**Two critical defects ship into a phase otherwise marked code-complete:**

1. **CR-01 (DRAFT-02 plant provenance latently broken):** The screen-level lookup for the parent bed compares `bed_drafts.id` against `plan_elements.imported_from` (which carries `import_items.id`). These are different UUID spaces — the match never fires. Right now this is dormant because `importRepo.ts:173` always sets `plant.bedDraftId = null` ("bedDraftId linkage handled in Phase 6-03 (promotion flow)" — a stale TODO from Phase 6 that was never actually addressed). The moment Phase 7 (or a future hotfix in Phase 6) wires `bedDraftId` for plants imported into beds, every plant-promotion will silently store `provenance.parentBedId = null` and place the plant at the bed's offset `+ 0.2` of a `null` parent → falls back to `(0, 0)`. The DRAFT-02 acceptance text reads "Bed-Draft auf Canvas ziehen → platziert als echtes Beet-Element mit `importedFrom`-Provenance" — beds satisfy this, but the broader interpretation "plants link to their parent bed via provenance" is broken by construction. The current test suite cannot catch it because all plant fixtures set `bedDraftId: null`.

2. **CR-02 (sync push fails on Hermes / older WebViews):** The `randomId()` fallback in `draftPromotionRepo.ts:23-28` returns a non-UUID string when `crypto.randomUUID` is unavailable. `plan_elements.id` is typed `uuid NOT NULL` in Postgres (Migration 014). On Hermes (default RN runtime in Expo SDK 55), every promoted element gets a non-UUID local id, succeeds local write to IndexedDB/SQLite (loose typing), then fails PostgREST insert with a uuid-format error and retries indefinitely in the outbox. The local row appears fine — the user sees the plan render on the source device — but a second device (Dirk's wife on her iPhone) will never receive the data. Combined with offline-first UX, the user will not notice until the next reopen on the other device, by which time the outbox may have backed up.

**Both gaps are documented in `.planning/phases/06.5-draft-sichtung-promotion/06.5-REVIEW.md` as CR-01 and CR-02 with proposed fixes.** Neither was addressed before phase close.

**Suggested follow-up:** Single hotfix plan that:
1. Fixes `review.tsx` parent-bed lookup to resolve via `bed_drafts.importItemId` (or carry `bed_drafts.id` through to `plan_elements.provenance.bedDraftId` during bed promotion and match on that).
2. Replaces `randomId()` with `expo-crypto`'s `Crypto.randomUUID()`.
3. Adds regression tests with non-null `bedDraftId` and a mocked `crypto.randomUUID = undefined` scenario.
